# Web UI 改版規劃(UI2)

提出日期:2026-11-09 狀態:完成(UI1–UI7,2026-11-14)

## 使用者需求
1. 介面更精緻、更有質感
2. 更好操作、資訊簡要
3. **一個畫面看完,不用上下捲動**;用頁籤切換不同資訊
4. **重要資訊在任何頁籤都要同時看得到**

## 現況問題
- 6 個區塊(需求、LLM、RAG、程式碼、虛擬 PLC、情境測試)由上往下排,桌機要捲動約 1.7 個螢幕高,手機更長。
- 檢查結果、模擬狀態、情境 PASS/FAIL 分散在不同區塊,捲動後就看不到。
- 程式碼編輯器是純文字框,沒有行號、語法色彩,錯誤無法對應到行。
- 情境腳本要手寫 JSON;波形圖訊號多時標籤重疊、STRING 顯示 NaN。

## 設計方向

### 版面:固定 100vh 的應用程式外框(整頁不捲動,只有面板內部捲動)

```
┌──────────────────────────────────────────────────────────────────────────┐
│ ◆ PLC ST Studio   專案:motor.st   Profile:[Siemens S7-1200 ▾]   ☾ / ☀   │ ← 頂列
├──────────────────────────────────────────────────────────────────────────┤
│ ● 檢查 0 錯 / 2 警告 │ ▶ 模擬 80 週期 OK │ ✔ 情境 3/3 PASS │ Claude·haiku │ ← 狀態列(常駐)
├────────┬───────────────────────────────┬─────────────────────────────────┤
│ 頁籤    │  ST 程式碼(常駐)               │  頁籤內容                        │
│        │  1 PROGRAM Motor               │  (依左側頁籤切換)                │
│ ✎ 產生  │  2 VAR_INPUT                   │                                 │
│ ▶ 模擬  │  3   start : BOOL;             │  例:「模擬」頁                   │
│ ✔ 測試  │  4 ...                         │   輸入開關 ⏻ start  ⏻ stop      │
│ ⇪ 匯出  │ ~5 b := 1;   ← 錯誤行標紅       │   輸出燈號 ● motor  cnt = 12    │
│ ❏ 文件  │                               │   波形圖(可縮放、游標讀值)        │
│ ⚙ 設定  │                               │                                 │
├────────┴───────────────────────────────┴─────────────────────────────────┤
│ 問題 (2)  輸出記錄   │ ⚠ L5: REAL assigned to INT …   點一下跳到該行        │ ← 底部抽屜(可收合)
└──────────────────────────────────────────────────────────────────────────┘
```

- **左:頁籤列**(icon + 文字),鍵盤 `Alt+1…6` 切換。
- **中:ST 程式碼編輯器常駐**:行號、ST 語法色彩、錯誤/警告行標記,與頁籤無關一直可見。
- **右:頁籤內容**,依任務切換(見下表)。
- **上:狀態列常駐**:檢查結果、模擬結果、情境結果、目前 LLM;點擊各項可直接跳到對應頁籤。
- **下:問題抽屜**:檢查/執行訊息列表,點擊跳到對應行;平常收合成一行。
- 中、右兩欄寬度可拖曳調整;寬螢幕(≥1600px)時右側可同時放兩個頁籤(例:模擬+測試)。
- 手機:頁籤移到底部導覽列,編輯器與頁籤內容改為上下切換;狀態列縮成彩色圓點。

### 頁籤內容

| 頁籤 | 內容(整合現有區塊) |
|---|---|
| ✎ 產生 | 需求文字/檔案、點位表(表格預覽)、使用 RAG 開關、「產生」按鈕;**產生過程時間軸**:檢索 → LLM → 檢查 → 情境 → 修正第 n 輪,各輪可看差異(diff) |
| ▶ 模擬 | 執行/暫停/單步/重設;**I/O 面板**(BOOL 輸入用開關、輸出用燈號、數值用即時數字);波形圖(標籤不重疊、STRING 以文字帶顯示、可縮放、游標讀值);輸入事件時間軸 |
| ✔ 測試 | 情境步驟**表格編輯器**(設定輸入 / 等待時間 / 預期輸出),可切換成 JSON;每步結果 ✔/✘ 與實際值 |
| ⇪ 匯出 | 各廠牌卡片(PLCopen / SCL / L5X / GX Works3 / Sysmac),顯示可匯出 ✔ 或不支援原因、方言警告,一鍵下載 |
| ❏ 文件 | RAG 文件清單(拖放上傳)、embedder 選擇、檢索測試 |
| ⚙ 設定 | LLM provider / model / base URL、API key(只存在記憶體,不寫入瀏覽器)、自動修正輪數、掃描週期 |

### 質感(視覺系統)
- 設計 token:色彩、字級、間距、圓角、陰影統一定義於 `:root`,亮色 / 暗色主題完整對應並可手動切換。
- 字體:介面用系統字 + Noto Sans TC,程式碼用等寬字;數字使用等寬數字(tabular-nums)避免跳動。
- 狀態色一致:成功綠、警告琥珀、錯誤紅、執行中藍,並搭配圖示(不只靠顏色,色弱可辨識)。
- 圖示:內嵌 SVG(不依賴外部 CDN,維持「僅本機、無外部相依」原則)。
- 細節:按鈕載入中狀態、操作完成的輕量提示(toast)、空狀態說明、焦點框、0.15s 過場動畫(尊重「減少動態」設定)。

### 不變的原則
- 仍然只用 Python 標準函式庫 + 單一 HTML(不引入 npm 建置流程);若需要編輯器元件,以「內嵌、可離線」為前提評估。
- 後端 API(`/api/*`)不變,現有 CLI 與測試不受影響。
- 保留現有元素 ID 或提供對應,讓 `tests/ui_e2e.js` 可逐步改寫而不是重寫。

## 里程碑(每個 ≤ 2 小時)

| 里程碑 | 內容 | 驗收 |
|---|---|---|
| UI1 外框與頁籤 | 100vh 外框、頂列、常駐狀態列、左側頁籤、程式碼常駐、底部問題抽屜;現有 6 區塊搬進頁籤,功能不變 | 1280×800 與 1920×1080 整頁無捲動;E2E 全過;各頁籤截圖 |
| UI2 視覺系統 | 設計 token、亮/暗主題切換、按鈕/輸入/卡片元件、SVG 圖示、toast | 亮/暗兩版截圖;對比度符合 WCAG AA |
| UI3 程式碼編輯器 | 行號、ST 語法色彩、錯誤行標記、問題列表點擊跳行、`Ctrl+Enter` 執行 | 錯誤可由問題列表跳到正確行 |
| UI4 模擬儀表板 | 執行/暫停/單步、I/O 開關與燈號、波形改進(標籤不重疊、STRING、縮放、游標) | 修掉已知波形問題;互動操作 E2E |
| UI5 產生時間軸 | 產生流程時間軸、各輪修正 diff、點位表表格預覽 | 用 mock provider 的 E2E |
| UI6 測試與匯出 | 情境表格編輯器(可切 JSON)、匯出卡片與不支援原因 | 不寫 JSON 也能建立情境並跑出 PASS/FAIL |
| UI7 響應式與收尾 | 手機底部導覽、可拖曳分欄、設定記憶(不含金鑰)、快捷鍵、無障礙檢查、README 截圖更新 | 390px / 768px / 1280px / 1920px 截圖;E2E 全過 |

建議順序:UI1 → UI2 → UI3 → UI4 → UI6 → UI5 → UI7。UI1 + UI2 完成後就能明顯感受到「一個畫面、有質感」的改變。
